# Theme-Sa · 공용 비밀번호 기록실

**주소:** https://dampd21.github.io/Theme-Sa/

방문자는 **공용 비밀번호 한 칸만 입력**합니다. 각자 GitHub 계정이나 토큰을 준비할 필요가 없습니다. 기록은 계속 `dampd21/Theme-Sa-data` 비공개 저장소의 `data/team.json`에 저장합니다. 별도의 웹 서버나 데이터베이스 서비스는 사용하지 않습니다.

> **운영 전 중요한 전제**
>
> 이 방식은 비밀번호를 아는 사람 모두에게 기록 저장소의 읽기·쓰기 연결 권한을 전달합니다. 로그인한 사람에게 GitHub 연결키를 숨기는 서버 인증 방식이 아닙니다. 비밀번호를 아는 사용자는 개발자 도구 등으로 복호화한 연결키도 알아낼 수 있습니다. **모두에게 같은 기록 관리 권한을 주어도 되는, 믿을 수 있는 소규모 그룹에서만 사용하세요.**
>
> F12·우클릭·소스 보기 단축키 제한은 가벼운 사용 제한일 뿐입니다. 브라우저 메뉴, 이미 열린 개발자 도구, 다른 프로그램 등으로 소스를 볼 수 있으며 완전히 차단할 수 없습니다.

## 관리자가 한 번만 설정하기

### 1. 기록 전용 Fine-grained 토큰 만들기

본인 GitHub 설정 → Developer settings → Personal access tokens → Fine-grained tokens에서 만듭니다.

- Resource owner: **dampd21**
- Repository access: **Only select repositories** → **Theme-Sa-data 하나만**
- Repository permissions: **Contents → Read and write**
- 만료 기간: 운영에 맞춰 짧게 설정하고 갱신 날짜를 관리

**공개 화면 저장소 `Theme-Sa`나 다른 저장소는 포함하지 마세요.** 접근 범위가 넓은 Classic 토큰은 공용 로그인 연결키로 받지 않습니다. 채팅에 노출된 예전 배포용 토큰도 사용하지 마세요.

### 2. Actions Secrets 두 개 등록

화면 저장소 `dampd21/Theme-Sa`의 다음 메뉴입니다.

**Settings → Secrets and variables → Actions → Secrets → New repository secret**

| Secret 이름 | 값 |
|---|---|
| `SITE_PASSWORD` | 팀원에게 알려줄 공용 비밀번호. **12자 이상**, 길고 추측하기 어려우며 다른 사이트에서 쓰지 않는 값 |
| `DATA_REPO_TOKEN` | 1번에서 만든 기록 전용 Fine-grained 토큰 |

두 값은 **Variables나 코드에 넣지 않습니다.** 채팅에 보내지 말고 GitHub 설정에 직접 입력하세요.

### 3. 배포 실행

**Actions → Deploy static content to Pages → Run workflow**를 실행합니다.

이 공용 로그인 버전의 코드가 `main`에 반영되어 있어야 합니다. Secrets가 없거나 토큰이 비공개 기록 저장소에 접근할 수 없으면 새 배포를 중단합니다. 기존에 성공한 Pages 배포가 있으면 그 사이트는 그대로 남습니다.

배포가 성공하면 모든 방문자는 `SITE_PASSWORD`에 설정한 비밀번호만 입력하면 됩니다.

## 어떻게 동작하나요?

```text
GitHub Actions의 Secrets
  SITE_PASSWORD + DATA_REPO_TOKEN
                ↓ 배포 시 암호화
공개 Pages의 vault.json (암호문만 포함)
                ↓ 사용자가 비밀번호 입력
브라우저에서 연결키 복호화
                ↓
GitHub API로 비공개 팀 기록 읽기·저장
```

- 비밀번호 자체를 프론트엔드에 평문으로 넣지 않습니다.
- 연결키는 **PBKDF2-SHA256(600,000회) + AES-256-GCM**으로 암호화합니다. 배포마다 무작위 salt와 IV를 사용합니다.
- 브라우저가 입력받은 비밀번호로 복호화를 시도합니다. 잘못된 비밀번호로는 GitHub API에 요청하지 않습니다.
- 공개된 암호문을 내려받아 **오프라인으로 비밀번호를 추측하는 시도**는 가능합니다. 단순 숫자나 짧은 단어 대신 긴 고유 비밀번호를 사용하세요.
- 비밀번호와 복호화된 연결키, 불러온 기록은 페이지 메모리에만 유지합니다. 앱이 localStorage나 sessionStorage에 보관하지 않습니다. 브라우저 비밀번호 관리자의 자동 저장 여부는 사용자 설정에 따릅니다.
- 새로고침·로그아웃 후에는 다시 비밀번호를 입력합니다.
- 서버 측 로그인, 사용자별 권한 분리, 사용자별 감사 기록, 사용자 한 명만 선택적으로 차단하는 기능은 없습니다. 커밋은 공용 연결키 소유자 명의로 기록될 수 있습니다.

## 비밀번호 또는 연결키를 바꿀 때

**비밀번호만 바꾸면 과거 접근을 완전히 차단할 수 없습니다.** 이전 암호문이나 복호화된 토큰을 보관한 사람은 기존 토큰이 유효한 동안 계속 접근할 수 있기 때문입니다.

접근자를 바꾸거나 비밀번호가 유출된 경우:

1. 새 기록 전용 Fine-grained 토큰을 발급합니다.
2. `SITE_PASSWORD`와 `DATA_REPO_TOKEN`을 둘 다 교체합니다.
3. 새 배포를 실행하고 정상 작동을 확인합니다.
4. **이전 GitHub 토큰을 반드시 폐기(Revoke)**합니다. 유출이 의심되면 우선 즉시 폐기하고 복구하세요.

토큰이 만료되면 새 토큰으로 Secret을 바꾸고 다시 배포해야 합니다. 토큰은 코드에 영구 내장되는 것이 아닙니다.

## 화면 기능

- 팀명 변경, 팀장 선택, 팀원 추가·수정·삭제
- 이름·학교·나이·역할·능력·메모 관리
- 검색·정렬, 카드형·목록형 보기
- 저장 후 GitHub에 커밋
- 편집하지 않을 때 약 30초마다 최신 기록 확인
- 파일 SHA 기반 저장 충돌 감지
- 미저장 초안 내려받기, JSON 백업·복원
- Galaxy S22 기준 360px 세로 화면, 읽기 쉬운 글씨와 한 칸 팀원 카드
- F12, Ctrl/Cmd+U, 일부 개발자 도구 단축키와 일반 영역 우클릭 억제
- 비밀번호·입력창 안에서는 붙여넣기를 위해 우클릭 메뉴 허용

소스 보기 제한은 끌 수 있습니다. 공개 `config.js`의 설정에 `basicSourceDeterrence: false`를 추가하면 됩니다. Actions가 설정 파일을 재생성하므로, 영구 변경하려면 워크플로의 공개 설정 생성 부분에도 반영하세요.

## 기록 저장·충돌

입력 후 **GitHub에 저장**을 눌러 성공 알림을 확인하세요. 입력만 한 내용은 저장되지 않습니다.

다른 사람이 먼저 저장하면 기존 기록을 조용히 덮어쓰지 않습니다. 내 변경을 파일로 보관하고 최신 기록을 불러온 뒤 필요한 내용만 다시 적용하세요. 오래된 JSON을 통째로 복원하면 최신 기록 전체를 의도적으로 바꾸는 작업이 됩니다.

## 개인정보

- 상세 집주소는 적지 마세요. 이름·학교도 필요한 범위로 제한하고 관련자의 동의를 받으세요.
- 비밀번호를 공유한 모든 사람에게 기록 관리 권한이 있습니다. 공유 인원이 적다는 사실 자체가 보호 장치는 아닙니다.
- GitHub는 수정·삭제 전 내용도 커밋 이력에 남깁니다. 앱에서 삭제해도 과거 이력이 영구 삭제되는 것은 아닙니다.
- 공개 저장소에 팀 기록·백업 파일·평문 연결키를 올리지 마세요.
- 기록 저장소 `Theme-Sa-data`를 Public으로 바꾸지 마세요.
- 화면 코드와 워크플로 수정 권한은 신뢰하는 관리자에게만 주세요. 악의적인 코드 변경으로 입력한 비밀번호나 연결키를 탈취할 수 있습니다.

## 배포 파일과 공개 설정

```text
.github/workflows/static.yml   # 공개 설정 생성 → 암호문 생성 → site만 배포
site/index.html               # 비밀번호 로그인·기록실·모바일 스타일
site/config.js                # 공개 저장소 좌표
site/vault.json               # CI에서만 생성, 암호문; Git에는 커밋하지 않음
tools/build-vault.mjs          # Node 내장 crypto로 암호문 생성
```

추가 npm 라이브러리나 외부 CDN은 사용하지 않습니다. `.gitignore`는 생성된 `site/vault.json`을 커밋에서 제외합니다. 암호문은 Pages 배포 산출물에는 포함됩니다.

기존 Actions **Variables**는 그대로 사용합니다. 비밀 값이 아닙니다.

| 변수 | 값 |
|---|---|
| `ARCHIVE_OWNER` | `dampd21` |
| `ARCHIVE_REPO` | `Theme-Sa-data` |
| `ARCHIVE_BRANCH` | `main` |
| `ARCHIVE_PATH` | `data/team.json` |

Pages Source는 **GitHub Actions**입니다. 워크플로는 `site` 폴더만 배포합니다.

## 오류 해결

- **기존 토큰 로그인 화면이 계속 나옴:** 새 코드가 `main`에 있는지, 새 워크플로가 성공했는지 확인하세요. 실패한 배포는 기존 사이트를 바꾸지 않습니다.
- **공용 로그인 설정이 준비되지 않음:** 두 Secrets를 설정하고 워크플로를 다시 실행하세요.
- **비밀번호가 맞지 않음:** 입력한 값과 `SITE_PASSWORD`를 확인하세요. Secret 변경 뒤에는 재배포해야 합니다.
- **연결키 만료·폐기:** 새 Fine-grained 토큰으로 `DATA_REPO_TOKEN`을 교체하고 재배포하세요.
- **403:** 토큰의 Contents 쓰기 권한, 실제 계정의 저장소 권한, 브랜치 규칙과 API 제한을 확인하세요.
- **409:** 저장 충돌입니다. 초안을 보관하고 최신 기록에 필요한 변경만 다시 적용하세요.
- **CSP 오류:** `index.html`의 JavaScript를 수정했다면 인라인 스크립트 해시도 갱신해야 합니다.

공용 로그인 변경은 테스트 비밀번호·가상 토큰과 모의 GitHub API로 검증했습니다. 실제 운영 비밀번호와 전용 토큰을 설정한 후 첫 배포에서 실제 저장·불러오기를 확인하세요. 기존 관리자 토큰 버전의 실제 저장 테스트와 이번 공용 비밀번호 버전의 검증 범위는 구분해야 합니다.
