# 퇴마사 · 비밀 기록실 — GitHub 공동 편집판

짙은 초록색과 부적 일러스트로 만든 팀 기록실입니다. GitHub Pages에 화면을 배포하고, **별도의 비공개 GitHub 저장소에 있는 최신 `data/team.json`**을 읽고 수정합니다.

> **중요: 로그인 방식이 바뀝니다.**
> 이 버전은 공통 비밀번호 방식이 아닙니다. 외부 서버 없이 GitHub만 사용하기 위해, 각 사용자가 자기 GitHub 계정의 **Fine-grained 개인 접근 토큰**으로 연결합니다. GitHub에 로그인해 둔 브라우저라도 토큰 입력은 별도로 필요합니다. 친구에게 계정이나 토큰을 공유하지 마세요.
>
> GitHub는 만 13세 이상만 계정을 사용할 수 있습니다. 12세 등 연령 조건을 충족하지 않는 친구가 직접 로그인해 쓰는 용도에는 맞지 않습니다. 나이 제한을 우회하거나 보호자 계정·토큰을 공유하지 마세요. 그런 사용자가 직접 공동 편집해야 한다면 GitHub 계정 인증 대신 별도 로그인 서버가 있는 구조로 변경해야 합니다.

---

## 1. 무엇이 가능한가요?

- 팀명 변경, 팀장 선택 및 변경
- 팀원 추가·수정·삭제, 능력 태그와 메모
- 검색·정렬, 카드형·목록형 보기, 모바일 화면
- 로그인 시 비공개 저장소의 최신 기록 불러오기
- 페이지 안에서 바로 GitHub에 저장 — 저장할 때마다 파일 변경 커밋 생성
- 편집하지 않을 때 약 **30초마다** 최신 변경 확인; 상단 **최신 기록** 버튼으로 즉시 확인
- 동시 수정 충돌 감지: GitHub 파일 SHA가 달라졌다면 덮어쓰지 않고 안내
- 미저장 변경 파일 내려받기, JSON 백업·복원
- 토큰과 팀 기록을 브라우저 저장소(localStorage·sessionStorage)에 저장하지 않음
- 공개 HTML에는 실제 팀원의 초기 개인정보가 없음

### 포함하지 않는 기능

- 공통 사이트 비밀번호, Actions Secrets 기반 웹 로그인
- 실시간 공동 타이핑, 자동 병합, 회원가입 페이지
- 서버 데이터베이스, Firebase·Supabase·Cloudflare 의존성
- GitHub 계정 생성·초대·토큰 발급 자동화

**수정란에 입력만 하면 저장되지 않습니다. `GitHub에 저장`을 누르고 성공 알림을 확인하세요.**

## 2. 전체 구조

```text
공개 화면 저장소                     비공개 기록 저장소
spirit-archive                       spirit-team-data
├─ site/index.html                   ├─ README.md
├─ site/config.js                    └─ data/team.json
└─ .github/workflows/pages.yml
         │                                  ▲
         ▼                                  │ GitHub REST API
GitHub Pages ───── 각자 토큰을 입력한 브라우저 ──┘
```

- 화면은 공개되지만, 기록 접근은 **GitHub의 실제 저장소 권한**으로 제한됩니다. 단순히 CSS로 가리는 방식이 아닙니다.
- GitHub Pages가 비공개 저장소를 대신 읽지 않습니다. **각 사용자의 브라우저가 자신의 토큰으로 API에 요청**합니다.
- Actions는 정적 화면을 배포하는 데만 사용합니다. 팀 기록을 공개 HTML이나 Pages 산출물에 복사하지 않습니다.
- 데이터 저장소가 Public이면 앱에서 연결·저장을 거절합니다.
- GitHub는 데이터 보관 서비스이므로 팀 정보는 GitHub에 전송되고 저장됩니다. 종단간 암호화 저장은 아닙니다.

## 3. 처음 한 번: GitHub 조직과 기록 저장소 준비

### 권장 구성: 조직(Organization) + 조직 구성원

GitHub의 Fine-grained 토큰에는 **외부 협업자·저장소 협업자에 대한 제약**이 있습니다. 여러 사람이 함께 편집하려면 개인 소유 저장소에 친구들을 단순 협업자로 추가하는 대신, 아래처럼 조직을 사용하는 것이 좋습니다.

1. 관리자가 GitHub에서 팀용 **Organization**을 만듭니다.
2. Organization의 **People → Invite member**에서 친구들을 **조직 구성원(Member)**으로 초대합니다.
3. 친구들이 초대를 수락합니다. 계정을 공유하지 않습니다.
4. 조직 아래 **비공개(Private)** 저장소를 만듭니다. 예: `spirit-team-data`.
5. 생성할 때 **Add a README file**을 선택해 `main` 브랜치를 먼저 만듭니다.
6. 기록 저장소의 접근 설정에서 편집할 친구나 팀에 **Write** 권한을 부여합니다. 읽기만 할 친구에게는 **Read** 권한을 줍니다.
7. 화면용 저장소의 코드 수정 권한은 관리자만 갖도록 제한하는 것을 권장합니다.

개인 소유 비공개 저장소는 **소유자 혼자 테스트할 때** 사용할 수 있습니다. 친구들 공동 편집은 조직 구성원 방식으로 준비하세요.

### 데이터 파일은 직접 만들 필요가 없어요

`data/team.json`이 없으면 첫 연결 때 **빈 기록실 만들기**를 안내합니다. 확인하면 팀명 `퇴마사`, 팀원 0명의 파일을 생성합니다. 잘못된 JSON 파일이 이미 있으면 덮어쓰지 않고 오류를 알립니다.

### 브랜치 보호 규칙

이 앱은 지정한 데이터 브랜치에 직접 커밋합니다. Pull Request나 별도 서명을 필수로 요구하는 규칙이 있으면 저장이 거절될 수 있습니다. 다른 중요한 코드 저장소의 보호 규칙을 약화시키지 말고, **팀 기록만 보관하는 전용 저장소**에서 정책을 결정하세요.

## 4. 공개 화면 저장소에 배포 파일 올리기

조직 아래 화면용 저장소를 하나 더 만듭니다. 예: `spirit-archive`.

일반적인 GitHub Free의 공개 Pages 배포를 위해 이 **화면용 저장소만 Public**으로 사용합니다. 다른 플랜·조직 정책에서는 가능한 Pages 구성이 다를 수 있습니다.

압축 파일을 풀고, 다음 구조 그대로 **화면 저장소의 루트**에 올립니다. 압축 파일 자체를 업로드하거나 `site` 내부만 루트에 옮기는 방식이 아닙니다.

```text
spirit-archive/
├── .github/
│   └── workflows/
│       └── pages.yml
├── site/
│   ├── index.html
│   ├── config.js
│   └── .nojekyll
├── README.md
└── SECURITY.md
```

> 운영체제에서 `.github` 같은 점으로 시작하는 폴더가 숨겨질 수 있습니다. 반드시 포함하세요. 웹 업로드에서 누락되면 GitHub의 **Add file → Create new file**로 `.github/workflows/pages.yml` 경로를 만들고 파일 내용을 붙여 넣으세요.

Git을 사용할 수 있다면 새로 만든 화면 저장소를 클론하고 위 파일·폴더를 복사한 뒤 커밋·푸시해도 됩니다. 토큰을 명령줄 URL이나 커밋에 넣지 마세요.

이전 로컬 HTML에는 초기 개인정보가 포함돼 있을 수 있습니다. **기존 HTML을 공개 저장소에 올리지 말고 이 배포본을 사용하세요.** 개인정보가 이미 커밋된 경우 현재 파일에서 삭제하는 것만으로 과거 이력까지 지워지지 않습니다.

## 5. Actions Variables 설정 — Secrets가 아닙니다

**화면 저장소**에서 다음 메뉴로 이동합니다.

**Settings → Secrets and variables → Actions → Variables → New repository variable**

| 변수 이름 | 입력값 예시 | 필수 여부 |
|---|---|---|
| `ARCHIVE_OWNER` | `our-spirit-team` — 기록 저장소를 소유한 조직명 | 필수 |
| `ARCHIVE_REPO` | `spirit-team-data` — 비공개 기록 저장소 이름 | 필수 |
| `ARCHIVE_BRANCH` | `main` | 선택, 기본 `main` |
| `ARCHIVE_PATH` | `data/team.json` | 선택, 기본 `data/team.json` |

조직명과 저장소 이름만 입력합니다. `https://github.com/...` 전체 주소를 넣지 마세요.

이 값들은 배포 때 공개 `site/config.js`가 되어 친구들의 연결 대상을 고정합니다. **비밀 값이 아니며 방문자가 볼 수 있습니다.** Actions Variables를 바꾼 후에는 배포 워크플로를 다시 실행해야 합니다.

### `TEAM_PASSWORD`나 GitHub 토큰을 Secrets에 넣나요?

**이 버전에는 필요 없습니다.**

- Actions Secrets는 배포 작업의 비밀 값입니다. GitHub Pages에 서버 로그인 기능을 만들어 주지는 않습니다.
- 공통 비밀번호나 쓰기 토큰을 빌드 과정에서 JavaScript에 넣으면 공개됩니다.
- 워크플로의 자동 `GITHUB_TOKEN`은 **화면 저장소의 Pages 배포 권한**에만 사용됩니다. 별도 비공개 기록 저장소 접근용 토큰이 아닙니다.
- 실제 기록 접근 토큰은 각 사용자가 자기 브라우저의 로그인 화면에만 입력합니다.

로컬 개발에서는 `site/config.js`에 저장소 좌표만 직접 적을 수 있습니다. GitHub Actions 배포 시에는 위 Variables의 값으로 이 파일이 다시 생성됩니다.

## 6. GitHub Pages 켜기

1. 화면 저장소의 **Settings → Pages**로 이동합니다.
2. **Build and deployment → Source**를 **GitHub Actions**로 선택합니다.
3. **Actions → Deploy spirit archive to GitHub Pages**를 엽니다.
4. **Run workflow**에서 `main`을 선택하고 실행합니다.
5. 초록색 성공 표시를 확인하고 배포 작업의 `github-pages` URL을 엽니다.

일반적인 접속 주소 예시:

```text
https://조직명.github.io/spirit-archive/
```

실제 주소는 Actions의 배포 결과를 기준으로 확인하세요. 사용자·조직 대표 저장소나 사용자 지정 도메인에서는 달라집니다.

기본 워크플로는 **화면 저장소의 `main` 브랜치**를 사용합니다. 다른 브랜치를 쓰면 `.github/workflows/pages.yml`의 `on.push.branches`도 수정해야 합니다. 이는 데이터 저장소의 `ARCHIVE_BRANCH`와 별개입니다.

공개 사이트가 열리면 로그인 화면만 보이는 것이 정상입니다. 기록을 쓰기 위해 Pages를 다시 배포할 필요는 없습니다. 기록은 GitHub API로 곧바로 비공개 저장소에 저장됩니다.

## 7. 친구마다 준비: 개인 토큰 발급

**각자 본인 GitHub 계정에서** 진행합니다. 먼저 조직·저장소 초대를 수락해야 합니다.

1. **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
2. Token name: 본인이 알아볼 이름. 예: `팀 기록실`.
3. Expiration: **7일 등 짧은 만료 기간**을 권장합니다. 만료되면 새 토큰을 발급합니다.
4. Resource owner: 기록 저장소를 소유한 **조직**을 선택합니다.
5. Repository access: **Only select repositories** → 비공개 기록 저장소 **하나만** 선택합니다.
6. Repository permissions:
   - **Contents: Read and write** — 수정·저장할 친구
   - **Contents: Read-only** — 보기만 할 친구
   - Metadata 읽기 권한은 자동으로 포함됩니다.
7. 조직 정책에 따라 승인이 필요할 수 있습니다. 관리자가 조직 설정의 개인 접근 토큰 요청을 승인합니다. 대기 중이면 접근에 실패할 수 있습니다.
8. 발급된 `github_pat_...` 토큰을 자신이 신뢰하는 **직접 배포한 기록실**에 입력합니다.

**GitHub 로그인 비밀번호를 입력하는 곳이 아닙니다.** 범위가 넓은 Classic PAT(`ghp_...`)는 이 앱에서 받지 않습니다.

읽기 전용 토큰에서도 편집 입력은 가능하지만 실제 저장은 GitHub가 거절합니다. 저장 오류가 나면 원격 기록은 바뀌지 않고 안내가 표시됩니다.

토큰의 Contents 권한은 그 저장소의 여러 파일에 적용되며 `data/team.json` 한 파일만으로 권한을 좁히는 것은 아닙니다. 따라서 데이터 전용 저장소를 쓰세요.

## 8. 평소 사용 방법

### 처음 기록 시작

1. 각자 토큰으로 연결합니다.
2. 최초 파일이 없다면 관리자가 **빈 기록실 만들기**를 확인합니다.
3. **팀원 추가**로 기록을 입력합니다. 첫 팀원은 팀장이 됩니다.
4. **GitHub에 저장**을 누르고 성공 알림을 확인합니다.
5. 다른 친구는 **최신 기록**을 눌러 확인하거나 자동 확인을 기다립니다.

### 이전 로컬 페이지의 기록 옮기기

1. 이전 페이지에서 JSON 백업을 내보냅니다. 상세 주소는 제외하세요.
2. 새 페이지에 연결합니다.
3. **저장 · 불러오기 → 기록 파일 불러오기**에서 JSON을 선택합니다.
4. **팀 전체 기록 교체** 확인을 읽고 저장합니다.

기존 `version: 1` 기록 형식을 지원합니다. 가져오기는 **모두가 보는 기록 전체를 바꾸는 작업**입니다.

### 친구가 먼저 저장했을 때

- 앱은 파일 SHA를 비교해 기존 변경을 조용히 덮어쓰지 않습니다.
- **내 변경 파일로 보관**하면 주소를 제외한 미저장 초안을 내려받습니다.
- **최신 기록으로 돌아가기**로 친구의 기록을 불러옵니다.
- 초안을 참고해 **내가 바꾼 부분만 다시 적용**하고 저장합니다.
- 오래된 초안을 통째로 복원하면 친구의 최신 변경이 사라질 수 있습니다. 자동 병합 기능은 없습니다.

### 네트워크 오류·저장 실패

- 초안은 메모리에 남고, 원격 기록이 저장됐다고 표시하지 않습니다.
- 네트워크가 끊겼다면 저장이 서버에서 완료됐지만 응답만 유실됐을 가능성도 있습니다. 초안을 내보낸 뒤 최신 기록을 확인하세요.
- 미저장 초안이 있을 때 상단 **미저장 변경 있음**을 누르면 보관·재시도 메뉴를 엽니다.

### 로그아웃·새로고침

- 우측 상단 자물쇠는 로그아웃입니다.
- 토큰과 기록을 페이지 메모리에서 비우며, 다음 연결 때 다시 입력해야 합니다.
- 화면 새로고침도 다시 로그인을 요구합니다. 자동 로그인 기능은 없습니다.
- 이 페이지의 로그아웃과 `github.com`의 로그아웃은 별개입니다.

## 9. 개인정보·권한 관리

- **실제 상세 집주소를 저장하지 마세요.** GitHub는 수정·삭제 전 내용도 커밋 이력에 남깁니다. 현재 파일에서 지워도 과거 기록이 바로 없어지지 않습니다.
- 표시명·가상 설정 위주로 사용하고 실제 학교 등은 꼭 필요한 범위로 제한하세요. 친구의 동의를 받고 기록하세요.
- 백업 파일에도 개인정보가 들어갈 수 있습니다. 공개 저장소·채팅방·게시판에 올리지 마세요.
- 저장소를 Public으로 바꾸면 과거 이력을 포함해 데이터가 노출될 수 있습니다. 설정을 변경하지 마세요.
- 토큰을 잃어버리거나 공개했다면 **즉시 GitHub에서 폐기(Revoke)**하고 새로 만드세요.
- 친구의 접근을 중단하려면 조직·저장소 접근 권한을 해제하세요. 이미 내려받거나 열람한 정보까지 회수할 수는 없습니다.
- 화면 코드 수정 권한은 신뢰하는 관리자에게만 주세요. 악의적인 화면 코드는 토큰을 노릴 수 있습니다. 사이트 주소를 확인하고 모르는 복제 사이트에 토큰을 넣지 마세요.
- 이 Pages 사이트에는 불필요한 외부 스크립트·광고·분석 코드를 추가하지 마세요. 전용 사이트 주소에서 운영하는 것을 권장합니다.

더 자세한 내용은 `SECURITY.md`를 참고하세요.

## 10. 자주 막히는 부분

| 상황 | 확인할 항목 |
|---|---|
| 배포가 `ARCHIVE_OWNER` 오류로 실패 | 화면 저장소의 Actions **Variables**에 필수 좌표를 설정하고 Run workflow 재실행 |
| 페이지가 404 | Pages Source가 GitHub Actions인지, `.github/workflows/pages.yml`이 포함됐는지, 배포 성공 여부 확인 |
| 저장소를 못 찾음 / 404 | 조직·저장소명, 브랜치, 초대 수락, 토큰의 Resource owner·선택 저장소·승인 상태 확인 |
| 토큰에서 조직을 선택할 수 없음 | 조직 구성원인지 확인. 단순 외부 협업자로만 초대된 경우 구성을 변경 |
| 읽기는 되지만 저장이 안 됨 / 403 | 사용자에게 Write 권한과 토큰에 Contents Read and write가 모두 있는지, 조직 승인·브랜치 규칙 확인 |
| 권한이 갑자기 사라짐 / 401 | 토큰 만료·폐기 여부 확인 후 새 토큰으로 연결 |
| Public 저장소를 거절함 | 화면용 Public 저장소가 아니라 기록용 Private 저장소를 선택 |
| 동시에 수정해서 저장 실패 / 409 | 초안을 보관하고 최신 기록을 불러온 뒤 필요한 변경만 재적용 |
| 파일 내용 오류 | UTF-8 JSON인지, 지원하는 version 1 형식인지 확인. 잘못된 파일은 자동 덮어쓰지 않음 |
| API 호출 제한 | 잠시 기다린 뒤 재시도. 백그라운드 탭과 편집 중에는 자동 확인을 건너뜀 |
| 파일 미리보기에서 연결이 안 됨 | 도구의 파일 미리보기는 네트워크를 제한할 수 있음. 배포된 **HTTPS GitHub Pages 주소**에서 사용 |

팀원은 최대 300명, UTF-8 JSON 파일은 최대 900KB입니다. 이미지·첨부파일은 지원하지 않습니다. 소규모 팀 기록용으로 설계했으며 잦은 대규모 공동 편집에는 데이터베이스 방식이 더 적합합니다.

## 11. 소스 수정 안내

별도의 빌드 도구 없이 정적 HTML과 공개 설정 파일로 동작합니다. 외부 CDN·폰트·스크립트 라이브러리는 사용하지 않습니다.

`index.html`에는 인라인 앱 스크립트의 SHA-256 해시를 사용하는 Content Security Policy가 있습니다. **JavaScript 내용을 바꾸면 CSP의 해시도 갱신해야 합니다.** HTML·CSS만 바꾸거나 `config.js`의 저장소 좌표만 바꿀 때는 앱 스크립트 해시가 달라지지 않습니다.

해시 갱신 예시(프로젝트 루트에서 Python 실행):

```python
from pathlib import Path
import re, hashlib, base64
p = Path('site/index.html')
s = p.read_text(encoding='utf-8')
script = re.search(r'<script>(.*?)</script>', s, re.S).group(1)
digest = base64.b64encode(hashlib.sha256(script.encode()).digest()).decode()
s = re.sub(r"sha256-[A-Za-z0-9+/=]+", 'sha256-' + digest, s, count=1)
p.write_text(s, encoding='utf-8')
```

## 12. 검증 범위와 현재 상태

브라우저 자동화와 **모의 GitHub API**로 다음을 검증했습니다.

- 로그인 전 기록 비노출, 잘못된 토큰·공개 저장소 거절
- 빈 기록 파일 최초 생성, 한글 포함 데이터 읽기·쓰기
- 두 사용자 간 새 기록 반영, SHA 충돌 방지
- 팀명·팀원·팀장 편집 및 삭제, 백업·복원
- 읽기 전용 토큰의 저장 거절, 손상된 JSON 보호
- 미저장 초안 보관, HTML 입력 이스케이프
- 로그아웃과 새로고침 시 세션·기록 초기화
- PC·모바일 레이아웃, 런타임·CSP 오류 확인

**실제 GitHub 계정·저장소에 배포하거나 실제 토큰으로 읽기·쓰기를 수행한 상태는 아닙니다.** 관리자가 위 설정을 완료한 뒤, 민감정보가 없는 가상 기록으로 2인 저장·불러오기를 먼저 확인하세요. API 권한·조직 정책·브랜치 규칙은 실제 환경에서 점검해야 합니다.
